Metrics & Queries

All metrics derived from raw Horizons data in orion_trajectory and, where noted, moon_trajectory. Formulas use SI-consistent units. All vector operations are in the ICRF geocentric frame. Two DuckDB views (v_kinematics and v_earth_moon) pre-compute the derived columns used throughout the dashboard.

GM_EARTH = 398_600.4418
km³/s²

Earth gravitational parameter (μ♁). Denominator in vis-viva, C3, and escape velocity. Do not round — precision matters for energy calculations near Earth escape.

GM_MOON = 4_902.8001
km³/s²

Moon gravitational parameter (μ☽). Used for lunar gravity magnitude and the gravitational crossover event. ~81.3× smaller than Earth's.

GM_SUN = 1.327_124_4e11
km³/s²

Sun gravitational parameter. Used only for approximate solar gravity — Sun's influence on Orion is non-trivial for precision work but small relative to Earth and Moon.

R_EARTH = 6_371.0
km — Earth mean radius

Subtracted from geocentric range to get altitude above the surface. Mean spherical radius — actual surface varies ±21 km due to Earth's oblateness.

R_MOON = 1_737.4
km — Moon mean radius

Subtracted from spacecraft-to-Moon range to get altitude above the lunar surface. The closest approach altitude is the dashboard's most dramatic single number.

FRAME = ICRF geocentric
500@399 · non-rotating

All X/Y/Z vectors are in the International Celestial Reference Frame with origin at Earth's center of mass. The frame does not rotate with Earth — converting to lat/lon requires GAST/GMST.

Section 1

Kinematics

Derived from orion_trajectory state vectors alone. No secondary bodies required. These are the headline numbers for the dashboard's velocity and position panels.

1
Speed
orion_trajectory · vx_kms, vy_kms, vz_kms
dashboard headline
Formula
v = √(vx² + vy² + vz²) km/s

The scalar magnitude of the velocity vector. The most important single number on the dashboard. Peaks near TLI burn (~10.8 km/s), drops during trans-lunar coast, rises again during lunar flyby, then climbs toward ~11 km/s approaching reentry. Pair with escape velocity to show whether Orion is bound or unbound from Earth.

Mission arc ~7.8 km/s (LEO) → ~10.8 km/s (TLI) → falling (coast) → rising (flyby approach) → ~11 km/s (reentry)
SQL — v_kinematics computed column 
SQRT(vx_kms * vx_kms + vy_kms * vy_kms + vz_kms * vz_kms) AS speed_kms
2
Altitude Above Earth's Surface
orion_trajectory · rg_km
v_kinematics
Formula
alt = r− R♁
R♁ = 6,371.0 km km

Geocentric range minus Earth's mean radius. Most meaningful during the early mission (LEO parking orbit, TLI) and reentry corridor. Conceptually thinner during deep trans-lunar coast — at 300,000 km from Earth, "altitude" is a stretch — but still a valid and displayable number throughout.

Altitude ~400 km (LEO parking) → rising (TLI coast) → ~400,000 km (max) → ~120 km (reentry interface)
SQL — v_kinematics computed column 
rg_km - 6371.0 AS altitude_earth_km
3
Transverse Speed
orion_trajectory · derived from speed + rr_kms
v_kinematics
Formula
v⊥ = √(v² − ṙ²) ṙ = rr_kms (range rate) km/s

The component of velocity perpendicular to the position vector — the part of the spacecraft's motion that isn't closing or opening distance from Earth. Together with range rate (rr_kms), it decomposes the full velocity into radial and tangential components. High transverse speed = mostly sideways; high range rate = mostly radial.

Note: Use GREATEST(..., 0) under the square root in SQL to guard against floating-point artifacts where speed² < rr² by a tiny margin near periapsis.
SQL — v_kinematics computed column 
SQRT(GREATEST(speed_kms * speed_kms - rr_kms * rr_kms, 0)) AS v_transverse_kms
MetricFormula / SourceUnitsNotes
speed_kms √(vx²+vy²+vz²) km/s Scalar speed. Primary headline KPI.
altitude_earth_km rg_km − 6371.0 km Altitude above mean spherical Earth. Use rg_km as cross-check against √(x²+y²+z²).
rr_kms raw: orion_trajectory km/s Range rate. Negative = closing, positive = receding. Display with "closing / receding" label rather than raw sign.
v_transverse_kms √(speed²−rr²) km/s Tangential velocity component. Guard GREATEST(..., 0) against float artifacts.
lt_sec raw: orion_trajectory s One-way light time. Divide by 60 for minutes. Simulates DSN ranging observable.
v_kinematics
Pre-computes speed, altitude, and transverse speed in a single pass over orion_trajectory.
SQL — app/sql.py view definition CREATE VIEW 
CREATE OR REPLACE VIEW v_kinematics AS
SELECT
    datetime_utc,
    jd_tdb,
    rg_km,
    rr_kms,
    lt_sec,
    -- Scalar speed from velocity components
    SQRT(vx_kms*vx_kms + vy_kms*vy_kms + vz_kms*vz_kms)             AS speed_kms,
    -- Altitude above Earth's mean spherical surface
    rg_km - 6371.0                                                     AS altitude_earth_km,
    -- Transverse (tangential) speed — perpendicular to position vector
    SQRT(GREATEST(
        (vx_kms*vx_kms + vy_kms*vy_kms + vz_kms*vz_kms) - rr_kms*rr_kms,
        0.0
    ))                                                                 AS v_transverse_kms
FROM orion_trajectory
Section 2

Orbital Mechanics

Two-body Keplerian derivations from orion_trajectory state vectors. Where orion_elements covers the same metric, prefer it — it uses JPL's full n-body solution and is more precise. These formulas remain authoritative for metrics not in the ELEMENTS output: orbital energy ε, C3, and gravitational accelerations.

4
Specific Orbital Energy
orion_trajectory · vis-viva equation
key event: ε = 0
Vis-Viva
v² 2 − μ♁ / r km²/s²

The cleanest single indicator of mission phase. When ε < 0, Orion is gravitationally bound to Earth (elliptical orbit). When ε = 0, it is exactly at escape velocity. When ε > 0, it is on a hyperbolic trajectory — unbound from Earth and coasting toward the Moon. Watching ε cross zero during the TLI burn marks the precise moment Orion escapes Earth's gravitational well.

Energy state ε < 0 (LEO, bound) → ε = 0 (escape threshold) → ε > 0 (TLI, hyperbolic) → ε < 0 again (return)
Not conserved: ε drifts during trans-lunar coast because the Moon and Sun exert non-negligible gravitational forces. The drift is physically real and reflects actual multi-body dynamics — it is not a numerical error.
SQL — v_kinematics extension computed column 
-- Specific orbital energy (vis-viva) — km²/s²
-- Negative = bound orbit. Zero = escape. Positive = hyperbolic.
(speed_kms * speed_kms / 2.0) - (398600.4418 / rg_km) AS orbital_energy_kms2s2
5
C3 — Characteristic Energy
orion_trajectory · mission design standard
v_kinematics
Formula
C3 = 2ε = v² − 2μ♁/r km²/s²

The standard mission design metric for departure energy — twice the specific orbital energy. C3 = 0 is Earth escape. For a trans-lunar trajectory, C3 is slightly positive (typically 0.5–2 km²/s² at TLI). Negative C3 means still in a closed Earth orbit. Negative C3 and negative ε are equivalent statements — C3 is simply the convention used in mission design documentation and trajectory trade studies.

C3 value negative (LEO) → C3 = 0 (escape) → ~0.5–2.0 km²/s² (TLI)
SQL — v_kinematics extension computed column 
-- C3 (Characteristic Energy) — km²/s²
-- Mission design standard: C3 = 0 is Earth escape threshold.
speed_kms * speed_kms - (2.0 * 398600.4418 / rg_km) AS c3_kms2s2
6
Eccentricity
orion_elements · ec (preferred) or Laplace-Runge-Lenz vector
ec = 1 crossover
LRL Vector
ê = (v×h)/μ♁ − r̂ e = |ê| — use orion_elements.ec dimensionless

Orbit shape. e = 0 is circular; 0 < e < 1 is elliptical; e = 1 is parabolic escape; e > 1 is hyperbolic (trans-lunar coast). The Laplace-Runge-Lenz vector is the two-body derivation — prefer orion_elements.ec directly, which uses JPL's full n-body solution and requires no vector arithmetic. The eccentricity vector points toward periapsis.

Hyperbolic caveat: Once e > 1, apoapsis (ad_km) and orbital period (pr_d) in orion_elements are undefined. Horizons returns sentinel values. Always filter ec < 1 before using those columns.
MetricFormula / SourceUnitsNotes
|h| (ang. momentum) |r × v| km²/s Conserved in two-body. Magnitude = √(hx²+hy²+hz²) where hx=y·vz−z·vy, etc.
inclination arccos(hz / |h|) deg Angle between orbital plane and ICRF equator. Prefer orion_elements.inc_deg. Loses physical meaning once Moon's gravity dominates.
orbital_energy v²/2 − μ♁/r km²/s² ε — vis-viva. Crosses zero at Earth escape. ε < 0 = bound, ε > 0 = hyperbolic.
v_escape √(2·μ♁/r) km/s Escape velocity at current distance. Pair with speed: when speed > v_escape, Orion is unbound.
c3 v² − 2μ♁/r km²/s² Characteristic energy = 2ε. Mission design standard; C3 = 0 is Earth escape.
eccentricity orion_elements.ec — Prefer ELEMENTS output. < 1 = elliptical, > 1 = hyperbolic (TLI onward).
semi_major_axis −μ♁ / (2ε) km Valid only when ε < 0. Negative (and meaningless for display) when hyperbolic. Use orion_elements.a_km.
Section 3

Earth–Moon Geometry

Requires moon_trajectory joined on datetime_utc. All metrics use the difference vector between Orion and Moon positions in the ICRF geocentric frame. The closest approach altitude is the single most dramatic number of the mission.

7
Spacecraft-to-Moon Distance
orion_trajectory JOIN moon_trajectory
flyby metric
Formula
Δx = x−mx
Δy = y−my
Δz = z−mz
 r_moon = √(Δx²+Δy²+Δz²) km

The primary metric for the lunar flyby. Computed from the difference of Orion's position vector and the Moon's position vector at the same timestamp. The minimum value of r_moon across the dataset gives closest approach distance and its timestamp. Do not use the geocentric range difference — that gives the radial range difference, not the actual 3D spacecraft-to-Moon distance.

r_moon ~384,000 km (departure) → falling (approach) → min value = closest approach → rising (departure)
SQL — v_earth_moon computed column 
SQRT(
    POWER(o.x_km - m.x_km, 2) +
    POWER(o.y_km - m.y_km, 2) +
    POWER(o.z_km - m.z_km, 2)
) AS r_moon_km
8
Altitude Above Moon's Surface
v_earth_moon · r_moon_km
dashboard headline
Formula
alt☽ = r_moon− R☽ R☽ = 1,737.4 km km

Spacecraft-to-Moon range minus the Moon's mean radius. The minimum value of this metric is the closest approach altitude above the lunar surface — the most dramatic single number of the mission. The Artemis II free-return trajectory brings Orion to within a few thousand kilometers of the surface, making this the headline flyby stat.

Mission highlight min = closest approach altitude → label as "LUNAR CLOSEST APPROACH"
Closest approach: Find the timestamp of minimum altitude_moon_km at startup and store it as a phase event. This becomes the "Flyby" phase marker on the scrubber and the peak moment in the lunar approach animation.
SQL — v_earth_moon computed column 
r_moon_km - 1737.4 AS altitude_moon_km
MetricFormula / SourceUnitsNotes
r_moon_km √(Δx²+Δy²+Δz²) km True 3D spacecraft-to-Moon distance. Do not use geocentric range difference.
altitude_moon_km r_moon_km − 1737.4 km Altitude above lunar surface. Minimum = closest approach. Primary flyby KPI.
rr_moon_kms (Δr · Δv) / r_moon km/s Closing speed relative to Moon. Negative = approaching. Dot product of Δr and Δv vectors divided by r_moon.
r_earth_moon_km √(mx²+my²+mz²) km Earth–Moon range at any timestamp. Context for how far out Orion is relative to total Earth-Moon distance.
em_fraction r_earth / r_earth_moon 0–1+ Normalized distance progress. Reaches ~1 at closest approach; exceeds 1 briefly if Orion passes beyond the Moon.
v_earth_moon
Joins orion_trajectory and moon_trajectory; derives all spacecraft-to-Moon metrics in one pass.
SQL — app/sql.py view definition CREATE VIEW 
CREATE OR REPLACE VIEW v_earth_moon AS
SELECT
    o.datetime_utc,
    o.rg_km             AS r_earth_km,
    -- Spacecraft-to-Moon distance vector
    o.x_km - m.x_km    AS dx_km,
    o.y_km - m.y_km    AS dy_km,
    o.z_km - m.z_km    AS dz_km,
    -- Moon range and altitude
    SQRT(
        POWER(o.x_km - m.x_km, 2) +
        POWER(o.y_km - m.y_km, 2) +
        POWER(o.z_km - m.z_km, 2)
    )                                                               AS r_moon_km,
    SQRT(
        POWER(o.x_km - m.x_km, 2) +
        POWER(o.y_km - m.y_km, 2) +
        POWER(o.z_km - m.z_km, 2)
    ) - 1737.4                                                      AS altitude_moon_km,
    -- Earth-Moon distance
    SQRT(m.x_km*m.x_km + m.y_km*m.y_km + m.z_km*m.z_km)         AS r_earth_moon_km,
    -- Fraction of Earth-Moon distance traveled
    o.rg_km / NULLIF(
        SQRT(m.x_km*m.x_km + m.y_km*m.y_km + m.z_km*m.z_km), 0
    )                                                               AS em_fraction
FROM orion_trajectory o
JOIN moon_trajectory m USING (datetime_utc)
Section 4

Gravitational Accelerations

Force per unit mass experienced by Orion from each gravitational body. Units are km/s² — convert to mm/s² (multiply by 10⁶) for display. The crossover event where Moon's pull exceeds Earth's is a labeled mission marker.

9
Earth–Moon Gravitational Crossover
v_earth_moon · derived at startup
phase event marker
Crossover when
μ☽ / r_moon² = μ♁ / r_earth² ratio > 1.0 = Moon dominates dimensionless

The point at which the Moon's gravitational acceleration exceeds Earth's. Related to but distinct from the classical Lagrange L1 point or the Hill sphere boundary. Compute the ratio at each timestep; the crossover is where the ratio crosses 1.0. Worth computing at startup and storing as a phase event — it's a clear, intuitive marker of when Orion enters the Moon's sphere of gravitational dominance.

Not the L1 point: The L1 Lagrange point accounts for the centrifugal force in the rotating Earth-Moon frame. The gravitational crossover is simpler — it is just the point where |a_moon| = |a_earth|. Both are interesting but they are different locations.
Accel ratio ≪ 1.0 (departure, Earth dominates) → ratio = 1.0 (crossover event) → ≫ 1.0 (flyby, Moon dominates)
Python — find crossover at startup app/phases.py 
# Gravitational acceleration magnitudes at each timestep
df["a_earth"] = GM_EARTH / (df["r_earth_km"] ** 2)
df["a_moon"]  = GM_MOON  / (df["r_moon_km"]  ** 2)
df["accel_ratio"] = df["a_moon"] / df["a_earth"]

# Crossover: first row where Moon's pull exceeds Earth's
crossover_mask = df["accel_ratio"] >= 1.0
if crossover_mask.any():
    crossover_time = df.loc[crossover_mask.idxmax(), "datetime_utc"]
MetricFormulaUnitsNotes
|a_earth| μ♁ / r_earth² km/s² Magnitude of Earth's gravitational pull. Dominant during LEO and early coast. Multiply by 10⁶ for mm/s² display.
|a_moon| μ☽ / r_moon² km/s² Magnitude of Moon's gravitational pull. Becomes dominant near closest approach. Requires r_moon from v_earth_moon.
accel_ratio a_moon / a_earth — Crossover event at ratio = 1.0. Find timestamp at startup; store as phase event.
|a_sun| (approx) μ☉ / r_sun² km/s² Approximate solar gravity. Requires sun_trajectory. Non-trivial for precision work; useful as a visualization element (show Sun pull direction).
a_net a_earth + a_moon + a_sun km/s² Vector sum. Direction relative to velocity vector determines whether Orion is accelerating or decelerating — drives the trajectory shape.

Orbital Elements from Horizons

orion_elements provides pre-computed osculating Keplerian elements at each timestep using JPL's full n-body solution. These supersede the two-body derivations in Section 2 wherever precision matters. The Section 2 formulas remain necessary for metrics not in the ELEMENTS output: orbital energy ε, C3, and gravitational accelerations.

ElementColumnUnitsNotes
Eccentricity ec — < 1 = elliptical, > 1 = hyperbolic (TLI onward). Key filter for apoapsis and period validity.
Semi-major axis a_km km Negative for hyperbolic trajectories — mathematically valid but hide or annotate for display when ec > 1.
Inclination inc_deg deg Relative to ICRF equatorial plane. Physically meaningful only during geocentric phases.
Longitude of ascending node om_deg deg Ω — where the orbit crosses the equatorial plane northward.
Argument of periapsis w_deg deg ω — angle from ascending node to periapsis direction.
True anomaly ta_deg deg ν — current angular position in orbit, measured from periapsis.
Periapsis distance qr_km km Closest approach to Earth center. Valid throughout (even hyperbolic). Subtract R_EARTH for periapsis altitude.
Apoapsis distance ad_km km Undefined when ec > 1. Horizons returns sentinel values. Always filter WHERE ec < 1 and use errors='coerce' (Python) or NULLIF (SQL).
Orbital period pr_d days Undefined when ec > 1. No closed orbit exists on a hyperbolic trajectory. Same filter applies.
Python — safe access pattern for hyperbolic sentinel values 
import pandas as pd

# ad_km and pr_d return Horizons sentinel values when ec > 1.
# Coerce them to NaN so downstream math doesn't silently propagate garbage.
df["ad_km"] = pd.to_numeric(df["ad_km"], errors="coerce").where(df["ec"] < 1)
df["pr_d"]  = pd.to_numeric(df["pr_d"],  errors="coerce").where(df["ec"] < 1)
Note

On Two-Body Approximations

What the approximations mean: Several formulas in Sections 2 and 4 use two-body (Keplerian) approximations — treating Earth (or Moon) as the only gravitational influence. The actual Orion trajectory is an n-body solution accounting for Earth, Moon, Sun, and higher-order perturbations (Earth's J2 oblateness, etc.).

This means metrics like eccentricity, semi-major axis, and orbital energy will drift slowly during trans-lunar coast even though they'd be conserved in a pure two-body problem. These drifts are physically real, not numerical errors. For a visualization dashboard the approximations are accurate enough — the numbers are correct in order of magnitude and visually interesting. For navigation-grade computation, use orion_elements directly.
